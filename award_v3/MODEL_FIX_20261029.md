# V3 描画時のぼけ・縮小へのモデル調整

## 確認した状況

撮影モードのCASE_Aは3か所を撮影してDONE。正常面・汚れは正しく分類されたが、ひび割れ画像ではstain=0.605、crack=0.395でuncertainだった。線はカメラ画像・切り出し画像に写っており、ROI抽出後の認識を調整した。

一律の鮮明化は撮影3枚では改善したが、別の合成画像で誤分類が増えたため不採用。推論の前処理・採用閾値0.85は変更せず、学習時に横方向の縮小・再拡大・ぼけ・微小ノイズ・反転を加えてモデルを調整した。

## 学習と選択

- 元の合成学習画像720枚だけで追加学習。1枚の元画像から無加工1枚・異なる劣化2枚を各エポックで作成。2160枚を独立した元画像数とは数えない。
- validationの元画像180枚から無加工と固定劣化2種類（540ビュー）を作り、検証成績でモデルを選択。Gazebo撮影3枚は学習にもチェックポイント選択にも使用しない。
- 追加学習36エポック、CPU、seed=84141。詳細はscripts/train_camera_robust.pyとmodels/camera_training_log.csv。
- 以前のモデルはmodels/wall_classifier_before_camera_fix.ptとして同梱。新旧のハッシュはmodels/camera_model_card.json。

## 評価（同じ閾値0.85）

| 確認対象 | 調整前の3分類正解 | 調整後の3分類正解 |
| --- | ---: | ---: |
| Gazebo撮影3枚（開発確認） | 2/3 | 3/3 |
| 既存の合成test 180枚 | 167/180 | 165/180 |
| 新しい合成画像600枚・通常画像 | 555/600 | 544/600 |
| 同じ600枚・ぼけと縮小を付加 | 416/600 | 549/600 |

通常画像の成績低下と、劣化画像での改善の両方を記録する。600枚の元画像とその劣化版は対になっており、1200枚の独立した画像ではない。新しい600枚はseed=800000以降で、学習・validation・既存test・シーン画像とは別。

ぼけと縮小を付加した600枚では、真のcrack 200枚のうち閾値を超えてcrackとしたものが40→138枚へ増え、非crack 400枚をcrackとしたものは1→1枚。通常600枚ではcrack採用176→198枚、非crackをcrackとしたものは2→2枚。全て合成画像であり実施設の性能ではない。

撮影3枚での調整後スコアはnormal=0.944、stain=0.876、crack=0.991。これは確認用3枚の値であり、走行中の全フレームの性能を示すものではない。

幾何投影＋簡易移動モデルの4条件では、未確定時停止を含む制御で所定の点検回数・DONE・停止距離を確認。実際のGazebo走行はこれから再確認する。撮影走行をひび割れ検出の成功には数えない。

## 導入

capture_fixを適用済みのpai_award_v3へ重ねる。V2は変更しない。モデルとモデル記録用のノード、評価用スクリプト等を更新する。通常の画像前処理、シーン、未確定時停止、near_target_lostは維持する。

Windows PowerShell：

```powershell
Expand-Archive -LiteralPath "$env:USERPROFILE\Desktop\pai_award_v3_model_fix.zip" -DestinationPath "$env:USERPROFILE\Desktop\pai_award_v3_model_fix" -Force
docker cp "$env:USERPROFILE\Desktop\pai_award_v3_model_fix\pai_award_v3_model_fix\." pai_ros2:/home/ubuntu/pai_award_v3/
docker exec -u root pai_ros2 chown -R ubuntu:ubuntu /home/ubuntu/pai_award_v3
```

Ubuntuターミナル：

```bash
cd /home/ubuntu/pai_award_v3
bash scripts/start_all.sh CASE_A auto
```

captureではなく通常のCNN走行を自動開始する。未確定の場合はREVIEW_REQUIREDで停止し、確認用画像を残す。起動時にCNN model: v3.0.2-camera-augmentationと表示される。まずCASE_Aで途中の点検停止が1回、最後にDONEになるか確認する。結果を確認するまで録画・公開は行わない。

runtime_model.jsonとsummary.jsonへ使用モデルのSHA-256を記録する。summarize_runs.pyは撮影走行を除外し、モデルごとの成功件数も表示する。古い失敗記録は削除しない。

既存のchecks/classification_test.json等は初期モデルの結果なので、新モデルの成績と混同しない。今回の結果はchecks/camera_model/へ別に収録した。

## 再現

```bash
python3 scripts/evaluate_camera_model.py --captures runs_v3/20261029_112525_167047_CASE_A_capture
```

このコマンドは既存180枚、新しい600枚、その劣化版、および指定した撮影3枚を比較評価する。撮影画像を学習へ入れる処理はない。
