# AIで標識を読み取る巡視ロボット

Physical AI応用1講座の最終課題。Gazebo上の差動二輪ロボットが、既知の直線コースを走行し、学習済みCNNによる標識認識を使って点検停止・画像保存・再出発を行います。

## 目的とAIの担当範囲

施設巡視の「認識→停止→記録→移動」を模したシミュレーションです。緑は「異常なし」、赤は「要点検」、それ以外は「背景」として分類します。

- **AI**：カメラ画像から切り出した領域を小型CNNで分類。
- **通常の制御**：前進速度、点検区間、終了位置、停止確認、状態遷移。
- **対象外**：実施設の損傷検出、未知の経路の探索、障害物回避。

緑を認識するとログを記録し、走行を継続します。緑の認識を走行許可の条件にはしていません。点検区間は座標で指定し、赤を2回連続で認識したときに停止します。

## 最短の起動手順

既存の講座用コンテナと同等の環境を前提にします。ZIPを展開した`pai_final`フォルダの中で、Ubuntuデスクトップのターミナルを3つ使います。学習済みモデルを同梱しているので、実演前の再学習は不要です。

Windows側で既存環境を起動する場合：

```powershell
docker start pai_ros2
```

ブラウザで `http://localhost:6080/` を開きます。このURLは同じPCのDockerコンテナ内デスクトップへの接続です。以下はすべてそのUbuntu内で実行します。

### ターミナル1：Gazebo

`pai_final`の場所へ移動し、次を実行します。

```bash
cd /home/ubuntu/pai_final
bash scripts/start_sim.sh
```

別の場所へ展開した場合は、`cd`の行だけその場所へ変更します。青いロボットと緑・赤の標識が表示されます。

### ターミナル2：ブリッジ

```bash
cd /home/ubuntu/pai_final
bash scripts/start_bridge.sh
```

ブリッジは動作中のまま残します。同じトピックの既存ブリッジが動いている場合は、それを終了してから起動してください。

### ターミナル3：巡視制御

```bash
cd /home/ubuntu/pai_final
source /opt/ros/humble/setup.bash
python3 scripts/patrol_run.py
```

`AI patrol`の画像画面をクリックし、半角英数で操作します。

- `s`：開始。カメラ・位置情報の受信、速度指令の購読先、開始位置を確認してから走行。
- `q`：終了。停止指令を送信して終了。

ウィンドウは640×480で起動し、端をドラッグして調整できます。撮り直すときは巡視制御を終了し、GazeboをCtrl+Cで終了して起動し直します。ブリッジは継続します。

## 制御の流れ

`READY → RUN → BRAKING → INSPECT → EXIT → FINAL_STOP → DONE`

| 条件・設定 | 内容 |
| --- | --- |
| 走行 | 前進速度指令0.2 m/s、角速度指令0 |
| 点検対象の判定 | オドメトリのxが5.0 m以上、かつ赤の認識が2回連続 |
| 停止確認 | 平面速度0.01 m/s未満、旋回速度0.02 rad/s未満を新しい位置情報で2回確認 |
| 記録 | 停止確認後、カメラ画像を`inspection.png`に保存 |
| 点検待機 | 停止確認後、実時間で3秒 |
| 終了位置 | xが6.5 m以上で停止指令を送り、速度による停止を確認 |
| データ途絶 | 実行中に画像または位置情報の最終受信から5秒経過するとFAULTへ遷移し停止指令 |
| 停止確認待ち | 20秒を超えるとFAULTへ遷移し停止指令を維持 |

`x`はオドメトリ基準の位置です。制御周期・加減速・情報更新間隔により、停止位置は閾値を少し超えます。赤を認識しない場合も終了位置で停止しますが、ログは`finished WITHOUT inspection`となります。

新しい実行記録は`runs/<日時>/events.csv`、点検した場合は同じフォルダの`inspection.png`に保存されます。異常時は再起動して開始位置からやり直してください。

## 学習・認識

入力はRGBの64×64画像です。構成はConv(3→16)→ReLU→MaxPool→Conv(16→32)→ReLU→MaxPool→Conv(32→32)→ReLU→Global Average Pool→Linear(32→3)。パラメータ数は14,435です。

- 学習画像40枚：normal 8枚、inspect 10枚、background 22枚。
- Adam、学習率0.001、100エポック、バッチサイズ16、乱数シード42。
- 明るさ係数0.8〜1.2と左右反転による拡張、クラス枚数の逆数による損失の重み付け。
- 全画像を学習に使用。学習内の独立した検証分割・早期終了は設けていません。
- 推論時は32・64・96ピクセルの窓を半分ずつずらし、64×64へ変換して分類。
- 各標識クラスについて、そのクラスが最大出力でスコア0.98以上の窓から最大スコアの1窓を表示。
- 表示枠は分類用の切り出し領域であり、標識全体の境界を推定したものではありません。

### データ収集

```bash
python3 scripts/collect_signs.py
```

画像画面で`g`（緑）、`r`（赤）、`n`（背景）を押し、対象をドラッグで囲んでEnter。`q`で終了します。距離や切り出し範囲を変えて収集しました。

### 学習

```bash
python3 scripts/train_signs.py
```

`models/sign_classifier.pt`と`models/training_log.csv`が更新されます。再学習すると同梱モデルを上書きするため、比較したい場合は先にモデルをコピーしてください。

### 追加画像の評価

```bash
python3 scripts/evaluate_signs.py
```

`g/r/n`で正解ラベルを選び、対象を囲んでEnter。画像と判定結果CSVを`evaluation/<日時>/`に保存します。`q`で集計して終了します。

### カメラ画像の自動認識だけを確認

```bash
python3 scripts/detect_signs.py
```

このコマンドは走行指令を送りません。

## 記録に基づく結果

| 区分 | 結果 |
| --- | --- |
| 学習画像40枚 | 最終エポックの正解率100%（汎化性能ではない） |
| 追加評価・normal | 4/4 |
| 追加評価・inspect | 3/3 |
| 追加評価・background | 8/8 |
| 合計 | 15/15 |

追加評価の根拠は`evaluation/20261020_172311_510340/results.csv`です。同じシミュレーション内で手動切り出しした少数画像での確認であり、独立した環境での検証や、動画全体の検出率評価ではありません。

動画収録に対応する`runs/20261021_104819/events.csv`では、赤認識・停止指令x=5.1695m、停止確認・画像保存x=5.3906m、点検待機後の再出発もx=5.3906m、最終停止確認x=6.5380mでした。停止確認から再出発まで約3.07秒、開始ログから最終停止確認までは約55.04秒です。処理負荷で所要時間は変わります。

## 制約と今後の改善

色と形が単純な標識を使う概念実証です。色のしきい値だけを使った手法との比較は未実施であり、この課題でのCNNの優位性は示していません。標識位置・照明・背景を変えた評価、誤認識対策、分類以外の検出方法との比較を今後の課題とします。
